# Character Unity

## Boundaries

- Foundry stays in its own repository and supplies public format/protocol primitives.
  Do not copy its implementations here or change existing hash APIs' meaning.
- Archive owns its database, original files and LanceDB. Other apps access it only
  through a read contract. The owner correction of 2026-10-13 keeps the existing
  Archive schema/database/files/LanceDB; new scrapes write into that same database.
  Do not point the separate native prototype at live Archive paths. Live writer
  takeover requires coordinating the old scheduler/index workers/optimizer first.
  See `docs/adr/0001-existing-archive-and-library-references.md`. Finish the Archive
  foundation before further viewer/editor work; Unity favorites will be references
  and changed saves will create forks, without duplicating original files.
- Architect and hub share `packages/api` and `packages/store`.
  `apps/api` hosts that API on Node or Workers; it is not a second implementation.
- Browser and portable code must not import Node adapters or native modules.
- `packages/architect` is Architect's editor ported verbatim with its global zustand stores
  (one editor per page). It persists through the unity API facade in `src/lib/api.ts`.
  Per-instance isolation is deferred (beads cu-1o2.5); do not "fix" the global stores ad hoc.
  `packages/editor` (scaffold form editor) is being retired. Host apps own auth and routing.
- Do not kill processes you did not start, discard legacy working-tree changes,
  or modify archived original bytes.

## Working here

Use Node 24 and pnpm 11.20.0, one workspace lockfile, TypeScript and ESM.
Run `pnpm bootstrap`, then `pnpm check` from the root. Bootstrap prepares the
commit-pinned external SDK in sibling `.unity-foundry-sdk` before installing the
workspace. Never reset a dirty SDK checkout or copy its implementation into Unity.
For focused changes use `pnpm lint`, `pnpm type-check`, or `pnpm test`.
Worker types are generated by `pnpm worker:types`; do not hand-edit them.
`pnpm build:worker` is a local dry run, not a deployment.

Store changes must pass both native SQLite and local D1 contract cases. Root
`pnpm test` generates `runtime/store-conformance.md` from the test results.
Never replace domain operations with an asynchronous transaction callback.
Append versioned migrations after the schema has been used with real data.

The package directories without manifests are documented future boundaries, not
implemented modules. Add a package only with its first real consumer. Keep status
and outstanding acceptance gates in `docs/implementation.md` accurate.
