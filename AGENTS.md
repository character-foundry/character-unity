# Character Unity

## Boundaries

- Foundry stays in its own repository and supplies public format/protocol primitives.
  Do not copy its implementations here or change existing hash APIs' meaning.
- Archive owns its database, original files and LanceDB. Other apps access it only
  through a read contract. The owner correction of 2026-10-13 keeps the existing
  Archive schema/database/files/LanceDB; new scrapes write into that same database.
  Do not point the separate native prototype at live Archive paths. Live writer
  takeover requires coordinating the old scheduler/index workers/optimizer first.
  See `docs/adr/0001-existing-archive-and-library-references.md`. Finish the Archive
  foundation before live takeover; editor/import cleanup is authorized while takeover is on hold. Unity favorites are exact-version references;
  changed saves create owned forks without duplicating inherited files. Read/open/
  export must not register asset rows or populate identity/search indexes. File
  import checks exact bytes before parsing, then Foundry content and asset identity;
  incomplete Archive identity coverage is an explicit refusal, not a silent miss.
  Unity-owned search projections go through an opt-in Archive admin endpoint into
  the same LanceDB. The Unity outbox is durable; no idle polling or embedding on
  browse. Failed/missing-provider work stays retryable. Do not enable these writers
  or run corpus identity indexing against live paths without owner coordination.
- Architect and hub share `packages/api` and `packages/store`.
  `apps/api` hosts that API on Node or Workers; it is not a second implementation.
- Browser and portable code must not import Node adapters or native modules.
- Stream consumers must consume or cancel their bodies. Keep shared response
  cleanup for HEAD and already-disconnected requests; the Node adapter cannot
  own a body it abandons before handoff. Test pre-return and active-read disconnects,
  not just successful downloads; never rely on FileHandle garbage collection.
- `packages/architect` retains useful Architect editor components but uses native Unity
  revision/import/asset contracts in `src/lib/api.ts` and `src/unity/`. Do not restore
  old server fallbacks or placeholder endpoints. Save commits document and staged
  assets together; recovery drafts do not autosave immutable server revisions.
  Each `EditorSession` owns its immutable workspace/client, vanilla stores, revision
  heads, recovery owner, staged assets and cancellation. Require the session provider;
  never add a singleton/current-session fallback. Auxiliary reads must not repin
  the editor's expected head. Shared browser preferences contain no card/draft state.
  The active `apps/web` library/viewer/editor/sharing/remotes shell uses native
  React Router and browser HTML; do not add Next aliases, shims or old CardsHub
  endpoints. Discover the host profile through `/api/client`, not failed-login
  guessing. Each library client captures one actor/workspace; JSON and protected
  binary reads use that same expected-account transport. Do not add a mutable
  global current client or cookie-only protected media/download shortcuts.
  Hub profiles must not load browser LLM credentials or call those providers.
  `packages/tokenizer` supplies the portable browser worker; the active app must
  not depend on the retired scaffold editor just to count tokens. Earlier Architect/hub
  hosts and their form/UI packages are retired; all profiles use `apps/web`. Retain browser-only
  IndexedDB data and safe upgrades; scaffold retirement is not authorization to
  reset that profile. Browser-only composition stays in-process over the existing
  `character-unity:architect` IndexedDB database; never fall back to a host API.
  Hosts own auth and routing. Standalone lorebook/preset/persona JSON lives in the
  same workspace store, not fabricated card identities or a separate database.
- Do not kill processes you did not start, discard legacy working-tree changes,
  or modify archived original bytes.

## Working here

Use Node 24 and pnpm 11.20.0, one workspace lockfile, TypeScript and ESM.
Run `pnpm bootstrap`, then `pnpm check` from the root. Bootstrap prepares the
commit-pinned external SDK in sibling `.unity-foundry-sdk` before installing the
workspace. Never reset a dirty SDK checkout or copy its implementation into Unity.
For focused changes use `pnpm lint`, `pnpm type-check`, or `pnpm test`.
Worker types are generated by `pnpm worker:types`; do not hand-edit them.
`pnpm build:worker` is a local dry run, not a deployment.

Store changes must pass both native SQLite and local D1 contract cases. Root
`pnpm test` generates `runtime/store-conformance.md` from the test results.
Never replace domain operations with an asynchronous transaction callback.
Append versioned migrations after the schema has been used with real data.

The package directories without manifests are documented future boundaries, not
implemented modules. Add a package only with its first real consumer. Keep status
and outstanding acceptance gates in `docs/implementation.md` accurate.
